# Apollo配置采集失败修复指南

## 问题描述
采集模板执行成功，但执行采集任务失败，报错："采集失败: Apollo Config Service地址不能为空"

## 根本原因分析

### 1. 配置参数传递机制差异
- **模板测试**：前端直接传递完整的配置参数进行测试
- **任务执行**：后端从模板内容解析配置，可能缺少必要参数

### 2. 配置优先级问题
Apollo配置的来源优先级：
1. 模板配置参数 (`configParams`)
2. 服务器实例配置 (`serverInstance.getApolloServerUrl()`)

当两个来源都缺少必需参数时，就会触发验证失败。

## 修复方案

### 方案1：完整配置模板（推荐）
确保Apollo采集模板包含所有必需配置：

```json
{
  "configServiceUrl": "http://apollo.example.com:8080",
  "appId": "your-app-id",
  "cluster": "default",
  "namespaces": "application,database,redis",
  "token": "your-access-token"
}
```

### 方案2：配置服务器实例
在服务器实例中配置Apollo参数：
- Apollo服务器地址
- Apollo应用标识
- Apollo集群名称
- Apollo命名空间列表

### 方案3：使用配置合并
系统已升级支持配置自动合并，确保：
1. 模板中有基本配置
2. 服务器实例中有补充配置

## 验证步骤

### 1. 使用数据库检查脚本

### 2. 模板测试验证
1. 进入采集模板管理页面
2. 选择Apollo模板，点击"测试"
3. 选择目标服务器进行连接测试
4. 确保测试成功

### 3. 任务执行验证
1. 创建采集任务
2. 选择已测试成功的Apollo模板
3. 执行采集任务
4. 查看执行结果

## 常见问题排查

### Q1: 模板测试成功但任务执行失败？
**原因**：模板测试使用实时配置，任务执行使用模板持久化配置
**解决**：检查模板内容是否完整保存，重新编辑模板确保配置正确

### Q2: 服务器实例Apollo配置不生效？
**原因**：模板配置优先级高于服务器实例配置
**解决**：确保模板中不要包含空值配置，或删除模板中的相关配置项

### Q3: 多个命名空间如何配置？
**正确格式**：`application,database,redis`（英文逗号分隔）
**错误格式**：`application, database, redis`（包含空格）

## 最佳实践

### 1. 模板配置建议
- 在模板中包含完整的Apollo配置
- 使用具体的应用ID和命名空间
- 配置合理的超时时间

### 2. 服务器实例配置建议
- 为Apollo类型的服务器实例配置专用参数
- 确保服务器地址可访问
- 配置正确的集群名称

### 3. 任务创建建议
- 先测试模板连接性
- 选择配置完整的服务器实例
- 设置合理的执行参数
